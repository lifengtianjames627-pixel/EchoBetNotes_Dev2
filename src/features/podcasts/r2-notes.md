# Cloudflare R2 播客音频接入

日期：2026-10-09

## 已实现
- 新播客音频使用私有R2存储；单文件应用上限为1,073,741,824字节，界面显示1 GB，六语言同步更新。
- 文件按16 MiB分片，不将整个1GB文件送入后端或内存。浏览器跨站上传权限可用时使用短期签名直传、最多三个并行分片；当前桶未配置CORS，自动改用管理员受控入口顺序转存每个16 MiB分片，不要求公开桶或扩大密钥权限。
- 上传显示进度，每个失败分片最多重试一次；失败后等待本批请求结束再中止并清理远端分片。
- 上传会话四向权限仅管理员；后端还核对登录者、owner_id、状态、过期时间、分片编号及代理分片的实际字节数。对象键只能由服务端生成，不能由调用者指定。
- 合并之前读取R2实际分片列表，核对数量和逐片大小；合并后及发布前校验实际对象大小、固定内容类型、16字节范围响应和音频文件头。仅完整且属于发布者的会话可以生成节目。
- Podcast共享数据不保存R2对象键、存储URI或永久音频地址。受限PodcastAudioAsset保存R2标记与对象引用；认证且能读到节目后，getPodcastAudio签发一小时GET链接。链接在有效期内属于持有者凭证，不承诺阻止下载或分享。
- 旧平台私有音频及封面逻辑保留；旧平台上传仍保持原50 MB限制，不把该路径误改成1GB。
- 凭据只在后端使用；兼容R2端点为账户地址或带当前桶路径的地址，严格限制HTTPS及官方R2主机，防止向其他域名发送凭据。

## 检查结果
- 当前既有检查配置下，规范检查、类型检查和生产构建通过；Browserslist数据旧提示仍在。
- R2桶访问通过；当前正式站点和预览站点的跨站直传权限未配置，真实上传因此走受控分片转存。
- 上限检查通过：1GB会话实际创建、返回64片、身份/大小持久化、中止持久化及记录删除；超1GB的请求在创建远端上传之前返回400。
- 真实上传窗口通过：选择52 MB WAV，超过原50 MB仍允许；更换为18 MB WAV后，真实点击发布，完成两片转存、R2合并、节目发布及会话published状态；原创建响应及已保存资产字段确认storage_provider=r2、size_bytes=18 MiB、对象键匹配。
- 真实收听入口通过：点击收听生成R2短期签名URL，浏览器实际加载原18 MB音频，解析时长正确。手机上传窗口和播放器均无文档级横向溢出。
- 第一次检查只读取请求摘要，未取得创建响应；随后读取详情时，验证工具把业务session_id作为敏感字段隐藏为[REDACTED]，造成验证脚本使用隐藏值查询时400，不是应用上传失败。恢复时只定位本轮唯一文件名、核对原节目ID和当前owner，重用本轮已上传文件建立独立显示夹具，确认音频加载，不新增存储文件。
- 本轮全部临时节目、资产、上传会话与18 MB R2原文件均已清理；1GB边界会话未实际发送1GB文件，已中止并删除。此前托管存储时期遗留的私有测试原文件不属于本轮清理范围。

## 尚未验证
- 实际传输完整1GB文件，不能用元数据上限检查冒充1GB实传。
- 普通成员/游客及跨账号真实身份权限；当前预览仅验证管理员身份，拒绝规则保留在后端与数据权限中。
- CORS直传分支、网络故障注入、发布并发、断网或关闭页面后的恢复、所有格式和六语言逐项交互。
- 私有桶的公开r2.dev或其他公开绑定应继续保持关闭；本接入不启用公开访问，也没有替用户修改桶的其他设置。
